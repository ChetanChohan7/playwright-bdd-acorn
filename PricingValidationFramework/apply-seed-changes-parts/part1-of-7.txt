rem ===========================================================================
rem apply-seed-changes.bat
rem
rem Updates an EXISTING PricingValidationFramework folder to the current
rem loader-values-batches-update code. The folder can be at commit 2dd63e1
rem (made by the original create-pricing-validation-framework.bat), already
rem have the seed changes (from the earlier version of this script or the
rem manual-update document), or be partly updated by hand.
rem
rem It applies:
rem   - seed: DataLoader "seed" command, Radar compares only (a missing
rem     baseline is an ERROR), data-loader pipeline Seed baselines stage and
rem     seedOnly parameter
rem   - follow-up: ICE as a Radar pipeline stage checking the scenarios that
rem     passed in that run's Radar report, scenario tags (test_tags CSV column,
rem     SCENARIO_TAG filter), local-settings.json for the Radar/ICE tests,
rem     VS Code debugging, "now" request times, blank endpoints ignored
rem   - .gitignore (one folder up, if present): local settings files ignored
rem

rem   - checks every file is one of those known versions before changing
rem     anything (line endings ignored, so a git checkout with CRLF is fine)
rem   - backs up every file it replaces or deletes to _backup-before-update
rem   - keeps your own .vscode\launch.json / tasks.json (any version this
rem     script didn't ship), writing the new ones beside them as
rem     launch.update.json / tasks.update.json; they never block the update
rem   - needs no admin rights; writes only to the folder and %%TEMP%%
rem
rem Usage:  apply-seed-changes.bat [project-folder] [/force]
rem         project-folder: the one holding PricingValidationFramework.slnx
rem                         (default: the folder this script is in)
rem         /force: apply even if some files are none of the known versions
rem                 (they are still backed up first)
rem ===========================================================================
